# 架構套件更新程序

本 ZIP 是不可變版本。未來修改不直接覆寫舊 ZIP，而是以舊版為基礎建立新目錄與新 ZIP。

## 1. 更新步驟

1. 複製上一版套件內容到新版本目錄。
2. 先修改 `VERSION`。
3. 在 `CHANGELOG.md` 新增版本與變更摘要。
4. 修改受影響的架構文件、Schema、範例與工作流。
5. 核心平台或權威邊界改變時新增 ADR。
6. 執行 JSON／Schema／連結／一致性驗證。
7. 重新生成 `MANIFEST.sha256`。
8. 產生新 ZIP，並保存 ZIP 自身的 SHA-256。

## 2. 版本規則

- `0.x.y-draft`：尚在架構討論與測試。
- `1.0.0`：正式建置基準。
- major：不相容的資料契約或平台責任改變。
- minor：新增相容功能、流程或 Schema 欄位。
- patch：文字、範例、錯誤與不影響契約的調整。

## 3. 變更提案格式

每次討論應至少指出：

- 要解決的問題。
- 影響的元件／文件。
- 是否改變資料 Schema 或狀態機。
- 是否需要資料 migration。
- 是否影響成本、SLA、安全或自動化。
- 回滾方式。

## 4. 與正式 repository 的關係

正式 repo 建立後，應將最新版架構套件解壓後的可維護來源放入 `docs/architecture/`，ZIP 發布物放入 `docs/releases/` 或獨立 Release。實作 PR 應在描述中引用相應章節或 ADR。
