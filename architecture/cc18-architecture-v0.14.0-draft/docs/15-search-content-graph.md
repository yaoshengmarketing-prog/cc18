# 搜尋內容圖與作品頁契約

## 1. 不是「多寫字」，而是覆蓋搜尋意圖

CC18 不以固定字數或關鍵字密度作為品質指標。每個頁型負責一組明確意圖，頁面只有在能提供獨立價值時才可索引。

| 頁型 | 主要搜尋意圖 | 必備獨特內容 |
|---|---|---|
| 作品頁 | 番號、片名、番號＋演員、作品評價 | 完整事實卡、原創影評、快速判斷、差異與有理由的推薦 |
| 演員 Hub | 演員作品、最新作品、題材傾向 | 可篩選作品、時間變化、常見系列／正式 Tag、代表作入口 |
| 系列 Hub | 系列作品、最新集、各集差異 | 系列定義、作品順序、差異摘要、演員分布 |
| Canonical Tag Hub | 類型作品、題材推薦 | Tag 定義、納入／排除標準、相鄰 Tag、代表與最新作品 |
| Latest／Archive | 新片、日期與月份查找 | 依作品頁日期排序、批次到站說明、可爬分頁 |

Source Tag 只是來源證據；未映射為 Canonical Tag 時不建立可索引頁。Candidate Tag 不產生公開 Hub。

## 2. 作品頁渲染順序

```text
Breadcrumb
→ H1（番號＋可追溯標題訊號）
→ 完整作品事實卡
→ 本站 9 秒預告／HTML5 video（存在才顯示）
→ 快速判斷卡
→ 原創影評
→ 影片 Evidence 所支持的節奏／結構摘要
→ 同系列差異
→ 適合／不適合條件
→ 同演員／同系列／相鄰題材推薦（每筆含理由）
→ CC18 原始作品 CTA
→ 方法、來源與更新資訊
```

「完整作品事實卡」直接渲染欄位，不由 AI 寫成自然語言段落。來源簡介可引用短摘要或明確標示來源，不可大量複製成本站正文。

## 3. 搜尋決策層欄位

- `quick_decision`: 一句核心判斷、主要看點、敘事密度、節奏、視覺呈現。
- `timeline_summary`: 開端／中段／後段的非露骨結構觀察；每項引用 Evidence window。
- `series_delta`: 與同系列近作的可驗證差異；沒有比較樣本時為空，不硬寫。
- `audience_fit`: 適合與不適合條件分開保存。
- `recommendations`: `movie_id`、`relation_type`、`reason`、共同訊號；至少一項差異訊號，避免同質推薦。
- `questions_answered`: 此頁實際回答的自然語言問題，只供 QA 與站內搜尋；不自動渲染成 FAQ。

FAQ 只有在頁面確實顯示問題與答案、答案非模板且能由資料或 Evidence 支持時才存在。不得為了 Schema 或關鍵字批量生成假 FAQ。

## 4. 可索引門檻

### 作品頁

- 事實必要欄位完整且來源 URL 有效。
- 原創影評通過證據、差異化與重複句 QA。
- 至少一個搜尋決策模組提供來源資料之外的新價值。
- canonical、標題、摘要、Breadcrumb 與站內連結有效。

### Hub

- Canonical 實體或正式分類，不使用搜尋參數 URL。
- 至少 3 部有效作品；不足時頁面可存在但 `noindex`。
- 有獨立定義、納入條件、關聯實體與可爬分頁，不是純卡片清單。
- 合併／改名使用 alias 與永久 redirect，不建立重複 Hub。

## 5. 技術 SEO

- URL 穩定：作品 `/reviews/{movie-id}/`，其他實體使用固定 slug；標題變更不改 URL。
- 所有重要站內關係使用真正的 `<a href>`，anchor 描述目的頁，不用「看更多」堆滿全站。
- sitemap 依作品、演員、系列、Tag 與 Archive 分割；`lastmod` 只在內容實質更新時改變。
- 參數篩選、排序與任意 Tag 組合不得形成無限可索引 URL；索引入口只使用策展靜態頁。
- 作品頁加入 `BreadcrumbList`。只有本站實際可播放的 9 秒 MP4 才能標記 `VideoObject`；不得把 CC18 的完整影片宣稱為本站影片。
- 9 秒 MP4 不建立 `Clip`／Key moments，因影片不足 30 秒且沒有實際深連結用途。
- 作品與成人題材頁採頁級成人內容標示；About、方法與政策等中性頁不應被錯誤套用全站標記。
- 圖片 alt 說明畫面用途與作品身分，不塞入一串 Tag。
- 外部 CC18 CTA 維持 `rel="sponsored noopener"`，可見文案明確標示目的站。

## 6. 信任與自動化揭露

全站提供可爬的「編輯方法」「資料來源」「AI 與本機分析方法」「更正政策」「商業關係」頁。作品頁顯示：

- 資料來源與最後驗證時間。
- 影評版本與實質更新時間。
- 使用 24 個全時間軸分布式抽樣窗時，明確寫出方法；不得改寫成「完整逐幕看完」。
- 哪些欄位是來源事實、哪些是本站評論。

這些不是免責文字，而是讓讀者與 QA 能驗證「誰、如何、為什麼」產生內容。

## 7. 自動 QA 指標

- `fact_mutation_count = 0`
- 來源簡介與正文長片段相似度低於門檻。
- 同批、同系列、同演員文章的句子與段落相似度低於門檻。
- 所有 Evidence claim 的 window reference 有效。
- 所有推薦目的作品存在，且 `reason` 不等於單純重複番號／演員／Tag。
- 每頁索引狀態有可解釋理由；薄 Hub 預設 `noindex`。
- Title／description 不重複、不用固定關鍵字串接。
- Structured data 與畫面可見內容一致，R2 影片 URL 可由搜尋引擎抓取。

## 8. V1 實作順序

1. 先完成事實卡與 Review 的權限分離。
2. 實作快速判斷、適合／不適合與有理由推薦。
3. 建立演員／系列 Hub 的獨立摘要與分頁。
4. Canonical Tag 達門檻才開放索引。
5. 加入 Breadcrumb、分割 sitemap、頁級 adult 標記與 Search Console 驗證。
6. 有足夠資料後才產生趨勢、比較與題材指南，避免初期薄頁。
